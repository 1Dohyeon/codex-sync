# 작업 일기

나중에 블로그를 쓰기 위한 글감 수집이다. 잘 쓴 글이 아니라 빠뜨림 없는 기록이 목적이다.

## 대상

- 인자가 없으면 지금 이 대화가 대상이다.
- 인자로 transcript(`.jsonl`) 경로를 받으면 그 파일이 대상이다. 세션 종료 훅([`hooks/worklog.sh`](../../hooks/worklog.sh))이 이렇게 부른다. 이때는 사용자에게 묻지 않고 끝까지 쓴다.
  - 한 줄이 메시지 하나다. `"type":"user"` 줄의 문자열 `content`가 사용자가 입력한 말이고, `"type":"assistant"` 줄의 `text`가 응답이다. 도구 결과는 에러 메시지 원문을 찾을 때만 본다.
  - 파일이 크면 `Read`의 `offset`·`limit`로 나눠 읽는다.
  - 저장소와 브랜치는 각 줄의 `cwd`·`gitBranch`에서, 날짜와 시각은 마지막 메시지의 `timestamp`를 로컬 시간으로 바꿔서 얻는다.
  - 세션 ID는 transcript 파일명에서 `.jsonl`을 뺀 값이다.
- 인자가 없으면 세션 ID는 `printenv CLAUDE_CODE_SESSION_ID`로 얻는다. 값이 없으면 틀의 `세션` 줄을 지운다.

## 저장 위치

`$WORKLOG_PATH/{YYYY}/{MM}/{DD}-{HHmm}-{주제}.md`, `$WORKLOG_PATH`는 [`rules/environments.md`](../../rules/environments.md)에 있다.

- 시각은 세션이 끝난 시점(지금 대화면 지금)의 로컬 시간이다. 인자가 없으면 `date '+%Y %m %d %H%M'`로 얻는다.
- `{주제}`는 세션에서 한 일을 2~5단어로 줄여 붙임표로 잇는다. 예: `worklog-스킬-설계`.
- 같은 이름의 파일이 있으면 덮어쓰지 않고 `-2`를 붙인다.

## 내용

아래 틀을 따른다. 해당 내용이 없는 항목과 절은 지운다. 기록할 주제가 없던 세션은 "한 일"만 남긴다.

```markdown
# {세션 제목 한 줄}

- 날짜: YYYY-MM-DD HH:mm
- 저장소: {owner/repo 또는 폴더명} ({branch})
- 세션: `{세션 ID}`

## 한 일

2~3문장 요약.

## 주제 1: {제목} [트러블슈팅 | 설계 결정 | 구현 | 탐구]

- 출발점: 무엇이 안 됐는지, 무엇을 정해야 했는지, 무엇을 만들려 했는지, 무엇이 궁금했는지.
- 살펴본 것:
  - {선택지·가설·자료 A}: 채택 또는 기각, 그 이유
  - {선택지·가설·자료 B}: 채택 또는 기각, 그 이유
- 결론: 실제로 한 것 또는 알아낸 것. 커밋이 있으면 해시와 메시지를 적는다.
- 배운 점: 다음에도 써먹을 수 있는 것.

## 글감 메모

블로그로 쓸 만한 포인트와 검색 키워드.
```

### 주제 나누기

- 세션에서 출발점이 다른 덩어리마다 주제 하나로 나눈다. 같은 출발점에서 이어진 시행착오는 한 주제에 둔다.
- 유형은 주제마다 하나만 붙인다. 구현하다 막힌 문제를 푼 것처럼 성격이 바뀌면 주제를 나눈다.

### 유형별로 꼭 넣을 것

공통 틀에 더해 아래를 빠뜨리지 않는다. 대화에 없으면 지어내지 않고 "확인하지 않음"이라고 적는다.

| 유형 | 출발점의 예 | 꼭 넣을 것 |
| --- | --- | --- |
| 트러블슈팅 | 훅이 파일을 만들지 못한다 | 에러 메시지 원문(코드 블록, 비밀값은 가림), 원인(끝까지 확인하지 못했으면 "추정"), 원인을 찾은 과정 |
| 설계 결정 | 저장 위치를 어디로 할까 | 기각한 선택지와 이유, 누가 골랐는지(사용자가 골랐는지, Claude가 제안했는지) |
| 구현 | 새 기능을 만든다 | 무엇을 어떻게 나눴는지(파일·구조), 검증 방법과 결과 |
| 탐구 | 이 도구로 이게 되는지 알아본다 | 확인한 출처(문서, 명령 출력, 링크), 확실한 것과 아직 모르는 것 |

## 규칙

- 대화에 실제로 있었던 것만 적는다. 빈 절을 그럴듯하게 채우지 않는다.
- 사용자가 고른 것과 Claude가 제안한 것을 구분해서 적는다. 기각된 선택지와 틀린 가설도 이유와 함께 남긴다. 블로그에서 가장 쓸모 있는 부분이다.
- 비밀값, 토큰, 고객 데이터, 내부 URL, 개인정보는 적지 않는다. 필요하면 `<내부 URL>`처럼 가린다.
- 저장한 뒤 그 파일을 `Grep`으로 한 번 더 검사한다. 걸린 값은 `<토큰>`처럼 가려서 다시 저장하고, 걸리지 않을 때까지 되풀이한다. 패턴은 아래와 같다(GitHub, OpenAI류, AWS, Slack, Google, JWT, 개인 키, Bearer, `키=값`).

```
\bgh[pousr]_[A-Za-z0-9]{20,}|\bgithub_pat_[A-Za-z0-9_]{20,}|\bsk-[A-Za-z0-9_-]{20,}|\bAKIA[0-9A-Z]{16}\b|\bxox[abprs]-[A-Za-z0-9-]{10,}|\bAIza[0-9A-Za-z_-]{30,}|\beyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}|PRIVATE KEY|Bearer [A-Za-z0-9._~+/-]{20,}|(?i:token|password|passwd|secret|api_?key)=[^\s<]
```
- 쓰기 전에 초안을 보여 주지 않는다. 저장한 뒤 경로만 알려 준다.
