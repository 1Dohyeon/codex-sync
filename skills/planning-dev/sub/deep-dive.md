# 깊은 분석

사용자가 요청하거나 계획 문서를 보강할 때만 쓴다. 기본 흐름에서는 쓰지 않는다. 요구사항 원문은 [`analyze-task.md`](./analyze-task.md)의 "요구사항 확보"대로 먼저 확보한다.

## 과거 유사 태스크 확인

먼저 `AskUserQuestion`으로 "과거 유사 태스크도 살펴볼까요?"를 예/아니오로 묻는다. 새 기능처럼 선례가 없는 태스크에서도 단어가 조금 겹친 어중간한 후보가 나와 분석을 엉뚱한 쪽으로 끌 수 있어서, 선례가 있을 법한지는 사용자가 정한다. 아니오면 아래 검색을 모두 건너뛴다.

예면 두 검색을 돌린다. 순위는 따로 나오며 섞지 않는다.

```sh
python3 ~/.claude/skills/planning-dev/hooks/tasksim.py <repo> <요구사항 원문 요약>
python3 ~/.claude/skills/planning-dev/hooks/prsim.py <저장소 경로> <요구사항 원문 요약>
```

- `tasksim.py`는 내 계획 문서(`~/plans/`의 진행 중·완료 폴더)를 보고, `prsim.py`는 저장소의 merge된 PR을 본다(`gh`를 못 쓰거나 PR이 없으면 커밋). 동료가 한 일이나 계획 문서를 쓰기 전의 일은 `prsim.py`에서만 잡힌다.
- `<repo>`는 지금 작업 중인 저장소 이름이다. 계획 문서 경로의 `{repo}` 자리에 쓰는 이름과 같다.
- `<저장소 경로>`는 지금 작업 중인 저장소의 경로다. 저장소 안에서 돌리면 `.`이다.
- `<요구사항 원문 요약>`은 원문 전체가 아니라 핵심 주제어 몇 개로 줄인 것이다. 원문을 그대로 넣으면 신호가 흐려진다.
- 라이브러리가 없거나 git 저장소가 아니어서 건너뛴다는 안내가 나오면 그대로 다음 단계로 간다. 실패로 취급하지 않는다.
- 유사도가 낮은 결과(0에 가까움)까지 끌어오지 않는다. 눈에 띄게 높은 것만 열어 본다. 계획 문서는 결과에 나온 폴더의 `requirements.md`를, 없으면 `tasks.md`를 `Read`로 열고, PR은 `gh pr view <번호>`로, 커밋은 `git show --stat <해시>`로 연다. 열어 보니 무관하면 버리고, 관련 있으면 무엇을 했는지 한두 줄로 남긴다.
- 찾은 게 있으면 분석에 "참고: 과거 유사 태스크"로 반영한다. 아래 서브에이전트를 부르면 호출 프롬프트에 함께 싣고, PR·커밋이면 변경 파일 목록도 싣는다. code-analyst가 그 목록을 `cochange.js` 입력으로 쓸 수 있다. 없으면 언급하지 않는다.
- 이건 `cochange.js`(code-analyst가 쓰는, git 커밋 기반 파일 동반 관계)와 다른 도구다. 이건 텍스트 유사도로 업무 단위 선례를 찾는다.

## 서브에이전트 분석

도메인과 코드를 격리해서 따로 보고 싶을 때 쓴다. **한 응답에서** 서브에이전트 2개를 동시에 호출한다. 순차로 부르지 않는다.

- [`domain-analyst`](../../../agents/domain-analyst.md)
- [`code-analyst`](../../../agents/code-analyst.md)

각 호출 프롬프트에 **확보한 요구사항 원문 텍스트를 그대로 실어서** 넘긴다. 링크나 파일 경로만 넘기지 않는다. 두 에이전트의 도구는 `Read`·`Grep`·`Glob`(그리고 `code-analyst`는 `Bash`)뿐이라 웹이나 Notion을 열 수 없어서, 위치만 받으면 원문 없이 분석하게 된다.

분석 범위를 좁힌 것이 있으면 함께 넘긴다. 과거 유사 태스크를 찾았으면 그것도 함께 넘긴다.

두 결과가 다 온 뒤에 취합한다. 새로운 분석을 만들지 않는다.

- [`analyze-task.md`](./analyze-task.md)의 "분석과 보고" 형식을 따르되, 도메인 설명을 앞에, 코드 분석을 뒤에 둔다. `ReportFindings`는 쓰지 않는다.
- 두 결론이 상반되면 해소하지 말고 양쪽을 나란히 둔다.
- **`domain-analyst`의 산출물은 최종본이 아니라, 상위가 사용자에게 풀어줄 1차 자료다.** 취합 뒤 사용자가 되묻는 후속 질의응답은 상위가 직접 한다. 서브에이전트를 다시 부르지 않는다.
